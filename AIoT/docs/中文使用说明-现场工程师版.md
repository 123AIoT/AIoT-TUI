# AIoT中文使用说明（现场工程师版）

> 面向对象：现场工程师、调试工程师、测试人员。  
> 目标：不需要编程背景，也可以独立完成连接、监控、写值、排障。

> 说明：完整总文档仍保留在 `docs/中文使用说明.md`。本文件是面向现场使用的精简独立版。

---

## 1. 你将用它做什么

AIoT 是一个终端工业通信工具，支持两种方式：

- **TUI 交互界面**（推荐现场使用）
- **CLI 命令行模式**（适合批量测试和脚本）

支持协议：OPC UA、MQTT、WebSocket、Modbus TCP/RTU、Siemens S7、Melsec、Omron、Delta、Xinje。

---

## 2. 启动方式

在仓库根目录执行：

```powershell
dotnet build
dotnet run --project AIoT/AIoT.csproj
```

- 不带 `read/write/browse/monitor` 子命令时，默认进入 **TUI**。

查看帮助：

```powershell
dotnet run --project AIoT/AIoT.csproj -- --help
```

---

## 3. TUI 快速上手（推荐）

## 3.1 连接步骤

1. 菜单进入 **Connection -> Connect...**
2. 选择协议
3. 填写 endpoint
4. 填写监控地址（可多个，逗号分隔）
5. 点击 Connect

## 3.2 常见 endpoint 示例

- OPC UA：`opc.tcp://localhost:4840`
- MQTT：`mqtt://127.0.0.1:1883`
- WebSocket：`ws://127.0.0.1:8080/ws`
- Modbus TCP：`modbus.tcp://127.0.0.1:502`
- Modbus RTU：`modbus.rtu://COM3?baud=9600&station=1`
- Siemens S7：`s7://192.168.0.10:102?plc=s1200&rack=0&slot=1`
- Melsec：`melsec://192.168.0.11:6000`
- Omron：`omron://192.168.0.12:9600`
- Delta：`delta://192.168.0.13:502?series=dvp&station=1`
- Xinje：`xinje://192.168.0.14:502?series=xc&station=1`

## 3.3 现场最常用快捷键

- `Tab`：切换面板
- `Enter`：订阅节点（OPC UA）
- `A`：新增监控地址（非 OPC）
- `W`：写值
- `Delete`：移除监控项
- `?`：帮助

## 3.4 协议专用输入（Connect 对话框）

- Modbus RTU：`baud` / `station`
- Siemens S7：`plc` / `rack` / `slot`
- MQTT：`clientId` / `qos` / `retain` / `topic`
- WebSocket：`subprotocol` / `address` / `header`
  - `header` 支持：`k1:v1;k2:v2`

## 4. CLI 常见命令（巡检/批量）

## 4.1 读取

```powershell
dotnet run --project AIoT/AIoT.csproj -- read opc.tcp://localhost:4840 "ns=2;s=Counter" --format json
```

## 4.2 写入

```powershell
dotnet run --project AIoT/AIoT.csproj -- write modbus.tcp://127.0.0.1:502 100 true --type bool --station 1 --format json
```

## 4.3 监控

```powershell
dotnet run --project AIoT/AIoT.csproj -- monitor ws://127.0.0.1:8080/ws --protocol websocket --ws-address '$last' --count 3 --format ndjson
```

## 5. 故障排查（现场版）

### 连不上

- endpoint 是否正确（IP/端口）
- 防火墙是否放行
- 协议是否选对（mqtt://、ws://、opc.tcp://）
- 有账号密码时是否正确

### 看不到数据

- 地址是否正确
- 设备是否在变化
- MQTT/WebSocket 常见原因：尚未收到上游消息（读的是缓存）

### 写入失败

- 类型不匹配（尝试 `--type`）
- 地址不可写
- 设备侧权限限制

## 6. 建议使用顺序

1. 先在 TUI 连通并看到值
2. 再用 CLI 复现同场景
3. 稳定后再交给自动化脚本
