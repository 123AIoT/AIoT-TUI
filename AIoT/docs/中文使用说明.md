# AIoT（aiot）中文使用说明（新手完整版）

> 适用对象：第一次接触本工具的工程师、测试同学、运维同学、以及需要让 AI Agent 调用 CLI 的开发者。  
> 当前版本能力：同时支持 **TUI（交互终端界面）** 与 **CLI（命令行）**，协议覆盖 OPC UA、MQTT、WebSocket、Modbus TCP/RTU、Siemens S7、Melsec、Omron、Delta、Xinje。

---

## 1. 这是什么工具？

AIoT（命令名常见为 `aiot`）是一个跨平台工业通信终端工具：

- **TUI 模式**：适合人工操作，连接设备、监控点位、写值、查看日志。
- **CLI 模式**：适合脚本与自动化，支持 JSON/NDJSON 输出，便于大模型 Agent 或 CI 调用。

## 2. 安装与准备

## 2.1 环境要求

- .NET 10 SDK（开发运行时）
- Windows / Linux / macOS 均可（本文示例以 Windows PowerShell 为主）

## 2.2 在源码目录直接运行（推荐新手）

在仓库根目录执行：

```powershell
dotnet build
dotnet run --project AIoT/AIoT.csproj
```

## 2.3 验证 CLI 是否可用

```powershell
dotnet run --project AIoT/AIoT.csproj -- --help
```

若你已经安装了发布版并有全局命令，可直接使用：

```powershell
aiot --help
```

## 3. 快速上手：TUI 模式（交互界面）

## 3.1 启动

```powershell
dotnet run --project AIoT/AIoT.csproj
```

不带 `read/write/browse/monitor` 子命令时，默认进入 TUI。

## 3.2 连接步骤

1. 打开菜单 **Connection -> Connect...**  
2. 选择协议（OPC UA / MQTT / WebSocket / 其他工业协议）  
3. 填写 Endpoint  
4. 填写监控地址（可逗号分隔多个）  
5. 点 Connect

## 3.3 各协议 Endpoint 示例

- OPC UA：`opc.tcp://localhost:4840`
- MQTT：`mqtt://127.0.0.1:1883`
- WebSocket：`ws://127.0.0.1:8080/ws`
- Modbus TCP：`modbus.tcp://127.0.0.1:502`
- Modbus RTU：`modbus.rtu://COM3?baud=9600&station=1`
- Siemens S7：`s7://192.168.0.10:102?plc=s1200&rack=0&slot=1`
- Melsec：`melsec://192.168.0.11:6000`
- Omron：`omron://192.168.0.12:9600`
- Delta：`delta://192.168.0.13:502?series=dvp&station=1`
- Xinje：`xinje://192.168.0.14:502?series=xc&station=1`

## 3.4 TUI 重点快捷键

- `Tab`：切换面板
- `Enter`：订阅节点（OPC UA）
- `A`：新增监控地址（非 OPC）
- `W`：对选中变量写值
- `Delete`：移除监控变量
- `?`：帮助

## 3.5 TUI 协议专用输入

- Modbus RTU：可直接填 `baud/station`
- Siemens S7：可直接填 `plc/rack/slot`
- MQTT：可填 `clientId/qos/retain/topic`
- WebSocket：可填 `subprotocol/address/header`
  - `header` 支持多项：`k1:v1;k2:v2`

## 4. 快速上手：CLI 模式（自动化）

## 4.1 基本语法

```text
aiot <read|write|browse|monitor> <endpoint> ... [options]
```

源码运行对应：

```powershell
dotnet run --project AIoT/AIoT.csproj -- <read|write|browse|monitor> <endpoint> ... [options]
```

## 4.2 四类命令

- `read`：读取一个或多个地址
- `write`：写入地址值
- `browse`：浏览（OPC UA 原生支持，其他协议多为缓存视图或不支持）
- `monitor`：持续监控输出

## 4.3 输出格式

- `--format text`：人类可读（默认）
- `--format json`：结构化 JSON
- `--format ndjson`：一行一条 JSON，适合流式处理

## 4.4 常用参数

通用：

- `--protocol <name>`：强制协议
- `--type bool|int|float|string|hex`：读写类型提示
- `--format text|json|ndjson`
- `--interval <ms>`：monitor 间隔
- `--count <n>`：monitor 收到 n 条后退出

认证：

- `--user <username>`
- `--pass <password>`

Modbus/Siemens：

- `--station`
- `--baud`
- `--plc --rack --slot`

MQTT：

- `--client-id`
- `--qos 0|1|2`
- `--retain`
- `--topic <name>`

WebSocket：

- `--ws-subprotocol`
- `--ws-header "k1:v1;k2:v2"`
- `--ws-address <name>`

## 4.5 CLI 示例

### OPC UA 读取

```powershell
dotnet run --project AIoT/AIoT.csproj -- read opc.tcp://localhost:4840 "ns=2;s=Counter" --format json
```

### Modbus TCP 写入

```powershell
dotnet run --project AIoT/AIoT.csproj -- write modbus.tcp://127.0.0.1:502 100 true --type bool --station 1 --format json
```

### Siemens S7 读取

```powershell
dotnet run --project AIoT/AIoT.csproj -- read s7://192.168.0.10:102?plc=s1200&rack=0&slot=1 DB1.0 --protocol siemens.s7 --type int --format json
```

### MQTT 发布（显式 topic）

```powershell
dotnet run --project AIoT/AIoT.csproj -- write mqtt://127.0.0.1:1883 "" 23.5 --protocol mqtt --topic sensors/temp --qos 1 --retain --format json
```

### WebSocket 监控（带附加参数）

```powershell
dotnet run --project AIoT/AIoT.csproj -- monitor ws://127.0.0.1:8080/ws --protocol websocket --ws-subprotocol telemetry --ws-header "X-Site:line1;X-Role:agent" --ws-address '$last' --count 3 --format ndjson
```

## 5. 协议能力说明（避免预期偏差）

- OPC UA：原生读写、原生订阅、原生浏览
- MQTT：`read`/`browse` 主要基于已接收缓存；`write` 为 publish
- WebSocket：`read`/`browse` 主要基于已接收缓存；`write` 为发送文本（常见 `address=value`）
- PLC 类协议（Modbus/S7/等）：监控多采用轮询模型

---

## 6. 常见问题排查

## 6.1 连不上

- 先检查 endpoint 是否可达（IP、端口、防火墙）
- 协议是否匹配（例如 MQTT 用 `mqtt://`，WebSocket 用 `ws://`）
- 凭据是否正确（`--user/--pass`）

## 6.2 monitor 没有输出

- 地址是否正确
- 设备是否正在变化
- 对 MQTT/WebSocket：是否已经收到消息（缓存语义）

## 6.3 写入失败

- 数据类型不匹配（加 `--type`）
- 地址不可写
- 设备权限限制

## 7. 如何编写一个 Skills 来调用本工具

下面给出一个通用思路：把 AIoT CLI 封装成“技能函数”，让 Agent 只关心参数，不关心命令细节。

## 7.1 Skill 设计原则

1. 固定命令模板（防注入）
2. 严格参数校验（协议、地址、qos 范围）
3. 固定输出格式（建议 `json` 或 `ndjson`）
4. 将 stderr 与 exit code 一并返回给上层

## 7.2 推荐 Skill 接口（示例）

输入参数：

- `action`: `read|write|browse|monitor`
- `endpoint`: 字符串
- `addresses`: 字符串数组（write 时取第一个）
- `value`: 写入值（write 必填）
- `protocol`: 可选
- `format`: `json|ndjson|text`（默认 `json`）
- 其他可选参数：`type/station/baud/plc/rack/slot/clientId/qos/retain/topic/wsSubprotocol/wsHeader/wsAddress/count/interval`

输出：

- `exitCode`
- `stdout`（结构化数据）
- `stderr`
- `commandLine`（便于审计）

## 7.3 PowerShell Skill 包装示例

```powershell
function Invoke-AIoTSkill {
    param(
        [Parameter(Mandatory = $true)] [ValidateSet('read','write','browse','monitor')] [string]$Action,
        [Parameter(Mandatory = $true)] [string]$Endpoint,
        [string[]]$Addresses = @(),
        [string]$Value,
        [string]$Protocol,
        [ValidateSet('text','json','ndjson')] [string]$Format = 'json',
        [string]$Type,
        [int]$Count,
        [int]$Interval,
        [string]$ClientId,
        [int]$Qos,
        [switch]$Retain,
        [string]$Topic,
        [string]$WsSubprotocol,
        [string]$WsHeader,
        [string]$WsAddress
    )

    $args = @($Action, $Endpoint)

    if ($Action -eq 'write') {
        if ($Addresses.Count -lt 1) { throw 'write 需要至少一个地址' }
        if ([string]::IsNullOrWhiteSpace($Value)) { throw 'write 需要 value' }
        $args += $Addresses[0]
        $args += $Value
    }
    elseif ($Addresses.Count -gt 0) {
        $args += $Addresses
    }

    if ($Protocol) { $args += @('--protocol', $Protocol) }
    if ($Type) { $args += @('--type', $Type) }
    if ($Count) { $args += @('--count', "$Count") }
    if ($Interval) { $args += @('--interval', "$Interval") }

    if ($ClientId) { $args += @('--client-id', $ClientId) }
    if ($Qos -ge 0 -and $Qos -le 2) { $args += @('--qos', "$Qos") }
    if ($Retain) { $args += '--retain' }
    if ($Topic) { $args += @('--topic', $Topic) }

    if ($WsSubprotocol) { $args += @('--ws-subprotocol', $WsSubprotocol) }
    if ($WsHeader) { $args += @('--ws-header', $WsHeader) }
    if ($WsAddress) { $args += @('--ws-address', $WsAddress) }

    $args += @('--format', $Format)

    $dotnetArgs = @('run', '--project', 'AIoT/AIoT.csproj', '--') + $args

    $stdout = & dotnet @dotnetArgs 2>&1
    $exitCode = $LASTEXITCODE

    return [pscustomobject]@{
        exitCode = $exitCode
        output = $stdout
        command = "dotnet " + ($dotnetArgs -join ' ')
    }
}
```

## 7.4 Agent 调用示例

- 读取 MQTT 最新温度：
  - `Action=read`
  - `Endpoint=mqtt://127.0.0.1:1883`
  - `Protocol=mqtt`
  - `Topic=sensors/temp`
  - `Format=json`

- 监控 WebSocket 流：
  - `Action=monitor`
  - `Endpoint=ws://127.0.0.1:8080/ws`
  - `Protocol=websocket`
  - `WsSubprotocol=telemetry`
  - `WsHeader=X-Site:line1;X-Role:agent`
  - `WsAddress=$last`
  - `Count=20`
  - `Format=ndjson`

## 8. 给新手的推荐学习路径

1. 先用 TUI 连一个本地/测试 endpoint（确认能看见值）
2. 再把同一个场景换成 CLI 执行
3. 最后把 CLI 封装成 Skill 给 Agent 调用

只要按这三步走，基本可以无障碍上手并稳定落地自动化。
